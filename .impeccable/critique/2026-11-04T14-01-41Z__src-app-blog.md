## Design Specificity Verdict

Authored for Overbound, mostly. Dark bands, condensed uppercase H1, green primary for actions, red signal only on header CTA. Article header reads as the site. Weak spot is taxonomy and copy, which look inherited from a CMS: 55 category options, slugs as labels. Hero copy fits any fitness blog. Nothing says the blog feeds the event: no OCR loop, no OPEN/RANKED, no "boucle".

## Overall Impression

Clean, dark, competent. Fold is wrong and cookie modal sits on the working area. Best thing: card grid and article typography. Biggest opportunity: move search, filters and first cards above the fold, and collapse the 55-option select into 4-5 editorial pillars.

## What's Working

- Card grid: 3 columns desktop, 1 mobile, consistent 16:10 image. Keeps 12 items scannable.
- Article header: clear editorial hierarchy, feels authored.
- URL-stateful filters (q, category, page), server-rendered. Shareable, back-button safe, search works without JS.

## Priority Issues

**[P1] Cookie modal blocks index and article.** Centred "Gestion des cookies" dialog (src/components/consent/CookieConsentBanner.tsx) covers search row and first cards at 1440, and bottom 40% at 375. Why: visitor cannot reach filters or first article without a decision. Fix: non-modal bottom bar, compact on mobile, "Tout refuser" equal weight to "Tout accepter". Consent itself stays. Scope: site-wide, not blog-only.

**[P1] 55-option category select with duplicates and dead ends.** BlogFilters.tsx renders every category as option. Duplicates: community/communaute, trainings/entrainement, nutrition/Nutrition, recovery/recuperation. Why: flat list of near-identical choices. Fix: in fetchBlogCategories (src/app/api/blog/blogQueries.ts) drop zero-count and merge variants; show 4-5 pillars as chips above grid; keep select for long tail. Sanity data cleanup likely needed.

**[P1] Card link wraps whole card; title clamped.** BlogArticleItem.tsx wraps full body in one Link, so accessible name = time + title + excerpt + "Lire l'article". h2 uses line-clamp-2, hiding full title. Why: screen reader reads full excerpt as link name; sighted users cannot read long titles. Fix: make h2 the only link (stretched link), aria-hidden the excerpt, allow 3 title lines, add category and date above title.

**[P1] Hero takes the first viewport.** Shared PageHero with two pills; at 1440x900 grid starts below fold. Why: discovery starts at fold; hero leads nowhere. Fix: compact hero variant for blog, or move BlogFilters above it; move "Voir les categories" and "Nos auteurs" under search row. Scope: PageHero is shared, change blog variant only.

**[P2] No result feedback.** No result count, no live region, empty-state link only when q. Fix: role="status" line "N article(s) pour ..." above grid; empty state adds category chips and always shows "Voir tous les articles"; error state adds retry.
